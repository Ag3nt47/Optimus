# Optimus feature coverage

Optimus implements independent Windows maintenance tools. This table explains the current behavior and recovery limits; it does not claim identical CCleaner rule databases, native algorithms, service protocols, driver catalogs or subscription coverage.

**Direct** means Optimus implements the operation. **Windows integration** means it uses a supported Windows/package-manager mechanism. **Optional external integration** requires an account, third-party tool or an existing user-provided script.

| Capability | Implementation | Current scope and practical limits |
| --- | --- | --- |
| Health/resource review | Direct, using Windows APIs | Current CPU, memory, free space, processes, program totals, startup and inventory notes. Multi-sample exact-lifetime CPU/I/O deltas and pressure-aware memory findings group applications by executable and explain potential slowdown contributors; no process is stopped by the diagnostic. No synthetic overall health score or guaranteed speedup. |
| One-click workflow | Direct | Runs only configured stages with actual stage-count progress, descriptions, process/log details and cancellation boundaries. New-install Full mode selects concrete consumer apps and privacy/cleanup modules after setup review. Existing individual choices persist; update installation retains saved approvals. |
| Maintenance observations | Direct, read-only | Before/after CPU, available RAM and per-volume free space from existing audits, separately labelled from deleted-file totals. Missing measurements stay unavailable. An exact, complete supported Run/Startup-folder inventory can establish or compare a private enabled-entry baseline; new/removed/changed registrations remain informational and confer no change approval. |
| Windows sign-in launch | Task Scheduler integration | Optional, owned current-user task launches the installed app. Startup can request normal Windows administrator consent once; denial keeps standard access. Settings checks effective status and explicitly repairs the saved choice. Automatic maintenance follows the separately saved cadence/scopes. The task itself is least privilege. Read-only startup probes do not request UAC or start maintenance. |
| Windows security and privacy | Native Windows integration | Reversible supported advertising/optional diagnostic preferences, Defender quick scan and source-linked MITRE mitigation context; selected Yes/No recommendations for provider-aware Defender/firewall/signature remediation. Security/Critical WUA patches need saved scope/agreements and fresh quiet-install gates; no automatic reboot. |
| Vendor-only and legacy/community support | Read-only source/inventory review | Official OEM routes, Update Catalog, 0patch and Legacy Update source information with compatibility/licensing gaps. No universal unofficial-patch search or unverified driver/firmware replacement. |
| Temporary/junk cleanup | Direct | Allowlisted temporary files, user/system error reports, application/Windows crash dumps and DirectX/NVIDIA/AMD/browser caches, subject to category, age, identity, active-process, lock and path checks. New optional categories require selection; cleared shaders rebuild and can temporarily stutter. Permanent deletion is limited to a fresh reviewed plan. |
| Browser cache cleanup | Direct | Recognized local Edge, Chrome, Brave, Vivaldi and Firefox cache profiles. One-click maintenance prompts separately for each open browser: request graceful close and clean, or skip that browser for this run. No force termination; remaining background processes, unknown state or a restart cause a skip. Cache-only cleanup preserves history, cookies, passwords and bookmarks. |
| Browser history, cookies and download-list cleanup | Direct plus browser-native fallback | Separate saved opt-ins for supported Chromium/Firefox SQLite stores, selected browser families, optional kept cookie domains, count previews and required private rollback backups. History/cookie records are cleared across all ages, independently of cache-file age. Firefox downloads use native browser controls. Passwords, bookmarks and downloaded files are excluded. Backups retain original private records; no secure-erasure claim. |
| Background analysis | Direct; opt-in | CPU, RAM, process memory, disk I/O and network counters at 2-60-second intervals. Starts off and never automatically stops applications. First samples establish baselines. |
| Process scheduling and allocation | Direct | Verified process identity, priority, logical CPU affinity, protected-process rules, allocation history and supported restoration. Higher priority or fewer cores is not automatically faster. |
| Application pause/resume | Direct | Selected eligible application-process suspension/resume with saved identity checks. It is not the same as CCleaner's private sleep engine and does not promise memory reclamation. |
| Process cleanup harness | Direct | All process inventory rows, including protected/inaccessible entries, with sampled evidence, parent/launch relationships and verified or inferred ownership labels. Explicit opaque actions from a fresh completed scan can pause an eligible process or disable an unchanged startup entry. No action is preselected. Exact identity/protection checks, bounded batches and expiry apply; no executable deletion or automatic uninstall. Private read-only CLI export supports local analysis. |
| Codex priority profile | Direct; optional | The configured Normal/AboveNormal/High target is applied only when explicitly requested. Existing priorities and external priority watchers are otherwise preserved. |
| Startup management | Direct | Supported Run registrations and Startup-folder shortcuts, backups and conflict-aware restore. Optional automatic disabling is limited to exact approved source/command/fingerprint snapshots; changed/protected entries are skipped. Registration presence is separate from Windows Startup approval state. |
| Third-party service controls | Direct/Windows integration | Supported protected-service checks and recorded stop/start-mode changes. System-critical and security services are excluded; device/application effects still need review. |
| Installed applications and removal | Windows integration | Registered desktop/Store inventory and the supported uninstall workflow. No general-purpose post-uninstall leftover detector or raw program-folder deletion. |
| Software updates | Windows Package Manager integration | Read update results and install an exact reviewed package ID. Automatic mode supports user-selected WinGet IDs or a separately approved all-supported scope with exact-ID exclusions, recognized current candidates, verified pin checks and explicit agreement consent. Localized, truncated or ambiguous scans fail closed for unattended installation. Catalog and installer behavior are controlled by the package provider. Microsoft Store update navigation is available separately; unsupported publishers still use their own updater. |
| Driver inventory and updates | Windows integration | All-present hardware/problem-code and installed signed-driver inventory, Windows Update Agent scan including applicable optional offers, manual installation and driver-package export. Coverage distinguishes offers, problems, unknown/incomplete scans and no offer. Official support links cover vendor-only routes; no offer is never labeled up to date. Saved exact-update approvals or device/provider/class/date rules can authorize later quiet installs in an elevated session after backup. Eligible present devices can be approved without a current update offer. Unknown/interactive/pending-reboot candidates are skipped; no automatic reboot or blanket driver replacement. |
| Disk analysis | Direct | Bounded selected-folder scans with large files/folders, file-type totals, incomplete/error reporting and reparse/placeholder exclusions. Logical sizes are not guaranteed reclaim estimates. |
| Local duplicate finding | Direct | SHA-256 content groups and identity/retained-copy checks. Optional saved folder/keeper/age/count rules authorize automatic recycling within those scopes; manual selected-file recycling remains available. |
| Curated Windows debloat | Direct/Windows integration | Concrete preview and per-target selection for curated consumer apps, Microsoft 365 consumer packages, Outlook, Edge and desktop Office workflows. Recovery varies by action. Bing Wallpaper, frameworks, security components, Store support and WebView2 are preserved by curated groups. |
| Existing Desktop Edge script | Optional external integration | Available only when the recognized user-provided script exists. Preview and script identity checks precede its own visible elevated/typed-confirmation workflow. It is not silently run by the normal Edge action. |
| Registry review and selective repair | Direct, narrowly scoped | Missing local executable targets in supported current-user App Paths registrations. Reviewed single-key removal retains raw value types and security descriptors for guarded restore. No HKLM, COM/CLSID, shared-DLL, installer or wholesale registry cleaning. |
| Personal OneDrive duplicate review | Optional external integration | User-registered public-client sign-in, encrypted token storage and bounded scans. Manual recycling uses metadata validation. Saved automatic drive/folder/keeper/age/count approvals additionally require bounded streamed SHA256 content comparison and fresh eTag/scope checks. Restore uses the OneDrive website bin. |
| Cloud provider coverage | Limited | Personal OneDrive only. Business/shared drives, SharePoint, Google Drive and Dropbox are unsupported. Real account behavior requires an explicit user connection and has not been exercised by offline mocks. |
| First-start setup and automatic maintenance | Direct | Setup questions preserve existing choices and require Save choices. Multi-choice groups have Select all / Clear all controls that retain eligibility checks, approval limits and separate consent. Manual, each app startup, daily while open, or weekly while open. Selected cleanup/debloat/profile stages may apply; software installation is restricted to selected exact WinGet IDs or a separately approved all-supported scope with agreement consent, pin protection and a fresh source-checked scan. Each duplicate/cloud/startup/driver module supports review or its own explicit saved apply approval. Old setup profiles require updated approval before automatic maintenance resumes. No maintenance service runs while Optimus is closed. |
| Windows audit scheduling | Windows Task Scheduler integration | Separate per-user daily read-only audits. Audit execution does not start setup, automatic maintenance or background sampling. |
| Recovery/history | Direct plus native recovery | Supported setting undo records, browser database rollback copies, local/OneDrive Recycle Bins and vendor/Windows reinstall or rollback routes. There is no universal undo for all operations. |
| Source Sandbox | Direct | Editable source working copy, Python AST save validation, bounded history, Revert, Original version, export and ready-checked restart. It is not an OS/container security sandbox. |
| Themes and motion | Direct | Adapted MIT Angerona themes, real-content reveal/reverse-close transitions, holographic orb minimize/restore and a pausing starfield. Reduced motion is supported. |
| Secure overwrite, free-space wiping and deleted-file recovery | No exposed automatic workflow | Normal cleanup/recycling does not securely erase storage or recover deleted files. A separately confirmed internal Windows Cipher helper is restricted to positively matched physical HDDs; it is not connected to one-click cleanup or advertised as a universal erasure guarantee. |

## How to assess a result

A scan is a preview or observation. An apply operation has its own confirmation, validation and recovery route. Reparse points, access failures, active applications, expired plans and changed identities can cause exclusions or refusal. A bounded scan must not be interpreted as a complete disk/account inventory. Cleanup access/read errors are retained and mark the preview incomplete. The workflow records incomplete cleanup scans as partial with errors instead of reporting a clean success. A recognized successful empty WinGet response is a normal no-update result; unknown output remains untrusted. Audit reports record the application version separately from the legacy Windows engine version.

Packaged maintenance operations use the native Windows PowerShell module search path to avoid module-loading failures from an inherited host environment.

Windows Update, WinGet, the Microsoft Graph connection and external scripts can require network access, agreements, permission changes or a restart. Local analysis, cache scanning and source editing do not require a cloud connection. No account is contacted merely by constructing the Cloud panel.

Core behavior is covered by disposable local fixtures, mocked external services and review-UI payload tests. Those tests do not establish successful live driver installation, real-account cloud authorization, every vendor uninstaller, or every Windows/hardware combination. Actual operations return logs and per-item results so their outcome can be assessed.
