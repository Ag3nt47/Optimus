# Maintenance comparison and enhancement priorities

Research date: **21 October 2026**. This is a feature and engineering comparison, not a claim that Optimus reproduces another product's implementation or paid service.

## Evidence and scope

The Optimus baseline is the source inspected in this checkout before the 0.6.2 enhancements, whose package version was 0.6.1. Relevant implementations include [feature coverage](FEATURES.md), [workflow/preferences](../src/optimus/workflow.py), [cleanup](../src/optimus/cleaner.py), [startup inventory](../src/optimus/engine/PersistenceInventory.ps1), [elevation](../src/optimus/elevation.py), and [outcome verification](../src/optimus/verification.py). Source inspection establishes intended behavior; it does not establish successful installation of every vendor update, real-account cloud access, or performance improvement on every computer.

CCleaner has been removed from the user's computer. Its current paid functions below are **publisher-documented claims**, not a new live paid-product test. An earlier private ledger described static frontend evidence from CCleaner 7.12.1526; that ledger neither tested its native engine nor established subscription behavior. It is not shipped in this repository. The official release history now lists **7.13.1573, dated today**. Newer release notes take precedence over older help pages when their descriptions differ. [CCleaner release history](https://www.ccleaner.com/ccleaner/version-history)

No competitor binary, subscription, private rule database, service protocol or asset is required by the proposed additions.

## Lessons from public maintenance projects

Licenses below describe the repositories inspected on the research date. Features can inform an independent design; code, rules and assets need their own applicable license review.

| Project and current license | Useful documented pattern | Practical Optimus lesson |
| --- | --- | --- |
| [BleachBit](https://github.com/bleachbit/bleachbit), GPL-3.0-or-later | Preview/select/clean and schema-validated CleanerML rules with OS and running-process conditions. The repository explicitly includes cleaner definitions under its license. [CleanerML docs](https://docs.bleachbit.org/cml/cleanerml/) | Independently author a versioned, nonexecuting, bounded cache-recipe schema and disposable fixtures. Do not import GPL definitions as MIT data or expose arbitrary process/registry actions through downloaded rules. |
| [Bulk Crap Uninstaller](https://github.com/BCUninstaller/Bulk-Crap-Uninstaller), Apache-2.0 | Rich application discovery, removal queues and leftover review. [Project site](https://www.bcuninstaller.com/) | Verify vendor uninstaller identity, serialize conflicting installers, show results, and separately review possible leftovers. An orphan candidate is not proof that a file is unused. |
| [WinUtil](https://github.com/ChrisTitusTech/winutil), MIT | Saved presets/configuration and grouped install/tweak/fix/update operations. | Export understandable choices; preview preset changes and preserve exclusions. Do not silently enable new destructive scopes when a preset gains features. |
| [Win11Debloat](https://github.com/Raphire/Win11Debloat), MIT | Concrete application selections, settings import/export and command-line profiles. | Keep exact package lists visible, version configurations, and record unsupported/managed-policy results. Preserve Bing Wallpaper and required frameworks; more disabled Windows features is not automatically a better result. |
| [UniGetUI](https://github.com/Devolutions/UniGetUI), MIT | Multiple package managers, per-package automatic updates/ignore choices, schedules and package-list backups. | Add provider coverage, defer/skip controls and operation history before adding adapters. Never translate a system-maintenance approval into blind pip/npm upgrades inside project environments. |
| [Winhance](https://github.com/memstechtips/Winhance), **PolyForm Shield 1.0.0** | Searchable configuration, app/optional-feature selection, power/settings profiles and configuration portability. | Feature reference only: its current [license](https://github.com/memstechtips/Winhance/blob/main/LICENSE.txt) contains a noncompete condition. It is not unrestricted permissive source for a competing Optimus app. No Winhance implementation is incorporated here. |

## Selected 0.6.2 work versus future roadmap

The 0.6.2 implementation includes **redirected and canonical user-temp coverage; automatic read-only resource observations before/after maintenance; verified startup drift comparison; clearer administrator/startup status and repair/probe paths.** Controller-local attempt tracking also prevents different open Optimus sessions from re-arming one another's startup maintenance. Fixture tests and packaged/local acceptance establish the supported behavior; this research alone does not establish every live provider outcome. The separate machine-specific temp-headroom companion is not automatically a portable core-app feature.

The following are **proposals**, not implemented functionality. P0 provides the greatest immediate value; P1 follows after a supported, fixture-tested design.

| Priority | Concrete addition | Required behavior before unattended use |
| --- | --- | --- |
| P0 | Consolidated maintenance preflight | Report actual elevation, pending reboot, active servicing/installers, free space on actual temp/system volumes and provider availability. Defer only affected stages with a reason; never convert an unavailable scan into “healthy.” |
| P0 | Threshold/idle cleaning while app is open | Saved category scopes, minimum interval, bounded bytes/count, idle/power conditions, fresh plans and the existing maintenance lease. Exclusions remain authoritative; no new category is implicitly approved. Inspired by Smart Cleaning. |
| P0 | Explain new/changed startup registrations | Reuse existing Run/Startup/task/service inventory; show baseline drift, parent/registration evidence and confidence. Require separate approval before disabling a changed or newly observed source. No claim that inference proves why Windows launched a process. |
| P1 | Already-closed browser cleanup trigger | Require stable closure/quiescence and a fresh preapply recheck. Restart/background activity means skip. An automatic trigger must not create a new permission to close unsaved browser windows. |
| P1 | Versioned application-cache recipes | Independently maintained paths, tested application versions, regeneration explanation, active-process guards and default-off new categories. Exclude account/session databases, downloaded content/models, projects and installed dependencies. BleachBit's declarative/tested approach is useful; its rules are not imported. |
| P1 | Update maintenance windows and per-version deferral | Separate check/install schedules, exact package/provider/version exclusions, pins, restart/power gates and saved agreement consent. Show WinGet/Store/OEM coverage separately. Use UniGetUI and current CCleaner controls as references. |
| P1 | Portable settings with previewed import | Version schema, show changed choices, preserve exclusions and validate supported fields. Never import cloud credentials or turn another machine's startup fingerprints, driver IDs, executable paths or approvals into authority to mutate this machine. |
| P1 | Private backup/report retention review | Display sensitive browser backups, retained bytes, age, recovery purpose and a user-chosen policy. Keep essential undo records distinct; explicitly disclose when pruning removes recovery. Do not call backup deletion secure erasure. |
| P2 | Normal bulk uninstall and leftover candidates | Queue supported vendor uninstallers; verify identity/results; keep failure details. Leftovers need independent evidence and review/quarantine. Do not delete program trees or implement a temporary-uninstall promise without a tested recovery model. |
| P2 | Extension/context-menu explanations | Read-only publisher/path/permission and launch-source inventory, with native management links. Cross-check browser/OS version and policy; no automatic removal based only on unfamiliar names. |
| P2 | More cloud providers | Separate adapters with least-scope OAuth, account binding, quotas, pagination, rate limits, token recovery and trash/restore tests, followed by an explicit real-account test. Age or size alone must not authorize deleting personal files. |

## Startup administrator request and verification

The existing Full preset saves `request_admin_on_startup=True`; existing Custom choices are durable. Normal interactive startup checks actual administrator status and, if requested, uses Windows `ShellExecuteW` with `runas`. Windows displays the consent/credential prompt. A command-line relaunch flag prevents loops; it is **not** evidence that the resulting token is elevated. Audits, probes, smoke tests and other read-only CLI paths do not request elevation. Cancellation leaves a usable standard session with protected changes deferred. [Microsoft ShellExecuteW documentation](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew)

Acceptance evidence should cover saved on/off choices, already-elevated startup, denied/failed requests, once-only relaunch, correct installed executable/shortcut paths, and protected-action deferral. A read-only probe can establish settings/path/token facts without exercising UAC. Interactive consent still requires the user; automated fixtures cannot prove a secure-desktop prompt was approved on this computer.

## How to demonstrate useful results

Keep deletion totals separate from logical scan sizes, drive free-space deltas, process RSS and CPU/I/O samples. A before/after observation should include elapsed time, sample availability and concurrent-workload caveats; it does not establish causation or a universal speedup. Recheck exact postconditions and preserve partial/failed/skipped outcomes. Relevant CCleaner release notes themselves describe fixes for incorrect update-success messages and misidentified applications, reinforcing the need for outcome and attribution tests. [Release history](https://www.ccleaner.com/ccleaner/version-history)

Use disposable fixtures for changed file/process identities, junctions/placeholders, locked databases, retained duplicates, expired plans, consent changes and partial failures. Mocked provider tests establish contracts; real accounts, applicable drivers and vendor installers need separately scoped integration evidence. Test power loss/cancellation and recovery records before adding new automatic mutation paths.

Whole-registry purges, indiscriminate working-set trimming, deletion of installer caches/recovery points, forced Edge removal, security-feature disabling and “all drivers are current” claims are not enhancement targets. The useful target is explainable maintenance within a known scope, with measured outcomes and recoverable setting changes.
