# Contributing

Use a feature branch, add meaningful tests for mutation boundaries, and run the test suite before opening a pull request. Windows-specific destructive operations must be exercised only with mocks or disposable fixtures in automated tests.

Keep the main screen at three buttons. Detailed controls belong in Settings; code editing belongs in Sandbox. Progress must reflect actual work stages. Never report a failed, cancelled or unsupported operation as successful.

Protect process identity, approved file roots, exact package selections, backup-before-mutation and stale-plan rejection. Do not add blanket registry cleaners, unknown driver downloads, silent source-agreement acceptance or automatic privilege changes.

Do not commit private reports, local paths, credentials, browser data, proprietary binaries or CCleaner rules/assets. New independent functionality belongs in the feature coverage document with its provider and limitations.
